# Migration workflow (target design)

- **Discover:** Inventory JS/TS/JSX/TSX/Java, React, Node, Spring, APIs, databases, external integrations and tests. Current CLI inventories files, Oxc top-level JS/TS declarations and static imports, GraphQL root SDL fields, heuristic JS/TS HTTP call candidates and Tree-sitter literal Spring controller routes. Only unambiguous relative JS/TS file targets are linked; matching HTTP call/Spring routes are unverified candidates. Java type attribution, inherited/dynamic routes and actual service behavior remain unknown until verified against source and tests.
- **Simplify:** Present evidence-backed opportunities (duplicate logic, pass-through layers, service consolidation). For every suggestion record origin, rationale, expected behavior, risk, and approval. Do not remove business logic just because a wrapper looks redundant.
- **Rewrite:** Simplify unjustified architecture in the **source**, then build the **target Rust** with appropriate types, module boundaries, error handling and tests (see the project `rust-best-practices` Skill). Planned stack: Dioxus/WASM UI, Axum/Tokio API, SQLx/PostgreSQL, Redis only for reconstructible caching. Media storage in PostgreSQL binary chunks is a design target, not a universal safe default: validate size, streaming, backup and cost.
- **Verify:** Capture baseline first; compare API contracts, integration and browser behavior; run cargo fmt, clippy and tests. Verify database migration, data preservation and rollback. Benchmark only with comparable workloads. Record unsupported features and unknowns.
- **Deploy:** Target single-node k3s with OCI images and Helm, Traefik ingress, a persistent PostgreSQL volume and ephemeral Redis. Confirm target Kubernetes context and require approval. Backup before destructive changes; deployment is verified only after rollout and smoke tests succeed.
- **Resume:** Keep version-controlled plans/decisions separate from the rebuildable SQLite index; record source revision/hash for each task. Do not confuse legacy and generated source indexes.

For now, the CLI implements bounded file/syntax/contract-candidate queries; source simplification decisions, code generation, behavior verification and deployment remain manual agent workflow, not automated features.
